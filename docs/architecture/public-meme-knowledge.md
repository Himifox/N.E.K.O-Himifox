# 公共梗知识库：可行性与实施方案

> 状态：提案，尚未授权扩展为通用知识库。
>
> 目标：让所有 N.E.K.O. 角色能够按需理解公开网络梗、ACG 用语和特定公开
> 圈层的固定用语；它不是用户记忆、角色经历、训练语料库，也不替代实时搜索。

## 0.1 运行策略修订：前台零等待，后台渐进学习

本方案采用“两条完全隔离的路径”：

```text
用户消息 ──> 本地词典/FTS 命中 ──> 当轮短卡片 ──> 正常模型回复
    │                │
    │                └─ 未命中：仍正常回复；不访问模型路由、百科或搜索站点
    │
    └─ 不发送原文 ───────────────────────────────────────────────┐
                                                                  ↓
来源目录、分类页、最近更新、已许可数据快照 ─> 限速后台同步 ─> 本地库增长
明确求知但未命中的规范化词条 ───────────────> 低频缺口队列 ────┘
```

- **前台热路径**只读本地 SQLite 索引；不得增加一次模型调用、百科请求或网页请求。
- **后台同步**由“本轮回复已送达”事件立即唤醒，不阻塞启动和对话；它由 Main Server
  托管、单实例、可取消、可观测。不得用任意固定秒数延迟替代该事件。
- 不将整段用户消息、会话 ID 或角色回复写入缺口队列；只有用户明确求知时，才可
  保存经规范化和最小化的候选词及处理状态。
- 已废弃“本地未命中后调用对话模型判断是否为梗”的语义路由。它会给共享/限流模型
  端点增加流量，且不适合承担后台同步决策。
- 新条目只能在下一轮及以后的对话中生效；第一次遇到尚未同步的新梗仍可能无法接住。

### 0.2 中断、退出与降级保证

后台同步是可丢弃的辅助工作，不能拥有对话或应用生命周期的控制权：

- 流式回复开始后，后台任务不得向会话消息队列写入状态、等待结果或改变回复内容；
  网络慢、来源限流和同步异常均不得截断当前回复。
- 用户关闭游戏/客户端或 Main Server 进入关闭流程时，先停止调度新批次，再取消在途
  HTTP 请求；只等待一个很短的、受限的清理窗口，不得为同步延迟退出。
- 单批写入必须是 SQLite 事务：完整提交后才更新 `last_success_at`；取消或崩溃时回滚
  该批，不产生半条目或重复 FTS 行。未完成同步可直接丢弃，下次按常规计划重新同步。
- 不要求断点续传、任务恢复或复杂的游标持久化；内容哈希和幂等 `upsert` 足以让下一次
  同步安全跳过已存在条目。
- 来源 API、网络、数据库或任务调度任一环失败时，保留旧库、标记该来源 `degraded` 并
  冷却重试；其他来源和正常对话继续运行。空库时角色照常回复，不展示同步失败给用户。

## 0. 当前实现基线

本计划不是从零开始。当前工作区已经有一个可运行的 `moegirl-knowledge`
原型，应当复用而不是推倒重写：

| 已有能力 | 当前位置 | 后续处置 |
| --- | --- | --- |
| 独立知识目录 | `ConfigManager.knowledge_dir` | 保留；扩展为公共知识根目录 |
| SQLite + FTS5 | `knowledge/moegirl_knowledge/store.py` | 保留存储与全文检索，执行显式 schema migration |
| 文本净化、提示注入清理 | `filters.py` | 保留，成为所有来源的入口校验 |
| 标题/别名/标签/正文检索排序 | `retrieval.py` | 保留并增加来源、范围和风险权重 |
| 萌百多候选检索 | `sources/moegirl_wiki_api.py` | 保留；它只服务萌百来源 |
| 同步锁、延迟、降级状态 | `sync.py`、`moegirl_knowledge_runtime.py` | 保留生命周期模式，改成按来源报告状态 |
| 内置工具与短卡片 | `main_logic/moegirl_knowledge_tool.py` | 先兼容，随后增加通用工具 |
| 回归测试 | `tests/unit/test_moegirl_*` | 作为迁移回归基线，新增 CHIME 与迁移测试 |

现有数据库 schema 只有一个 `entries` 表，字段已经包含标题、别名、标签、正文、
来源 URL、许可证、哈希、同步时间和状态；但没有 `source_id`、`scope`、来源版本、
风险标签或关系模型。`schema_version=1` 仅被写入元数据，尚无迁移机制。这是
首个必须补齐的工程缺口。

## 1. 先给结论

当前的 `moegirl-knowledge` 原型适合验证 SQLite、FTS5、来源归属及安全降级，
但**不能直接宣称是通用梗知识库**。主要问题是：

1. 首轮萌百检索只得到 4 条有效记录，自动搜索覆盖率不足；
2. 萌百偏 ACG，不能覆盖“疯狂星期四”或主播观众的圈层梗；
3. “梗百科”站点不等于可复制的数据集；未明确许可的网页不能批量缓存；
4. 主播梗没有通用真值来源。未指定公开社区时，系统无法判断某词属于哪位
   主播、是否过时，或是否带有冒犯性；
5. 单一 `content` 字段无法表达同一词在不同圈层中的不同含义和不同出处；
6. 当前同步状态只描述整个萌百任务，无法显示“CHIME 已就绪但萌百本轮失败”。

建议采用“**尽量广的可用基础库 + 合规来源适配器 + 圈层范围提示**”的三层
方案。产品目标是让角色能理解梗的大致含义与语气，不是为每个条目完成学术考据。
它不依赖人工逐条录入；只在接入一个新来源时确认其访问与再利用边界。

## 2. 数据源决策

| 来源 | 首期角色 | 是否持久化 | 条件 |
| --- | --- | --- | --- |
| [CHIME](https://github.com/yuboxie/chime) | 中文文字梗基础库 | 是 | 固定版本、MIT、保留版本与引用 |
| 萌娘百科 | ACG 补充与增量 | 是 | 保留 URL/许可；仅存通过相关性验证的条目 |
| [Geng Baike](https://gengbaike.heyfe.org/) | 新梗候选 | 否（默认） | 当前页面标示“保留所有权利”；得到书面授权或明确许可后才可同步正文 |
| 主播/社区资料页 | 指定圈层补充 | 仅许可后 | 用户配置来源 URL 或创作者公开授权清单，不采集评论区、弹幕或私密群聊 |
| 热词词表 | 候选发现 | 否 | 词表没有释义真值；必须通过其他可引用来源验证 |

CHIME 包含 1,458 条短语型中文梗，字段包括含义、出处、例句、类别与粗俗/
冒犯标签。它是可立即落地的“首装基础”，但它是研究数据集而不是持续更新
服务：出处字段可能为空，且不能把模型生成的来源补全当作事实。

## 3. 范围与非目标

- 只在问题与梗、作品文化或圈层语境有关时检索；每轮最多返回 1 张卡片。
- 绝不写入 `recent.json`、`facts.json`、`reflections.json` 或 `persona.json`。
- 外部内容仅是参考，不能执行其中的指令，也不能被角色叙述为亲身经历。
- 不批量抓取 B 站评论、弹幕、付费内容、登录后内容或绕过反爬/权限的接口；
  它们既不是可靠释义库，也有隐私、版权和平台规则风险。
- 不自动把“相关梗”“衍生梗”“同一出处”写成同义词；但可把来源提供的标题、
  重定向和明确别名直接用于命中。

## 4. 运行时架构

```text
许可明确的数据集 ──┐
萌百 API ──────────┼─> 来源适配器 -> 校验/净化 -> SQLite + FTS5
已授权的梗百科 ────┘                               │
                                                    ├─> search_public_meme_knowledge
候选词表/实时站点 ─> 候选队列（不持久化正文） ─────┘
```

仍由 Main Server 托管：不新增第四个服务，不依赖插件。所有后台同步任务可
取消、可观察、失败时保留旧库。数据库仍在
`<knowledge_dir>/public-meme-knowledge/knowledge.db`，不默认上传云端。

## 5. 数据模型

第一阶段不直接引入完整知识图谱。先在现有 `entries` 表上做**最小可用迁移**，
这样可保留已经通过的 FTS、upsert 和损坏库降级逻辑。迁移时只处理可再生知识库，
绝不迁移用户记忆。

```text
entries(
  id, title, aliases, tags, content, summary,
  source_id, source_item_id, source_url, source_license, source_version,
  scope, risk_tags, expires_at, content_hash, synced_at, status
)

source_state(
  source_id, enabled, persistence_policy, last_success_at, last_attempt_at,
  status, entries, added, updated, unchanged, failed, last_error, version
)

relations_v2(可选，第二阶段后再加入)
  from_entry_id, to_entry_id, relation_type, source_entry_id
)
```

`source_id + source_item_id` 是唯一来源键，取代当前只适合萌百的
`source_page_id` 唯一索引。`scope` 至少区分 `public`、`acg`、`creator:<id>`
与 `community:<id>`；`risk_tags` 保存 CHIME 的粗俗/冒犯标签及未来来源的过期
提示。首期遇到同词不同义时保留为不同条目，不自动合并。只有来源明确支持时
才在第二阶段建立 `alias_of`；否则使用 `related_to` 或不建立关系。

FTS5 索引 `title`、已验证别名、摘要、标签和正文。另从 `title` 与已验证
`aliases` 构建内存可重建的多模式词典索引（自动机）：它扫描**完整用户句子**，
而非依赖引号、固定问句或手写正则。检索排序为：精确标题/别名 > 许可明确且
高置信来源记录 > 范围匹配 > 标签/正文命中 > 新近度。每轮最多注入一张卡片，
并要求长度、风险标签和置信度通过阈值。

## 6. 导入与同步

### 6.1 CHIME 首装导入

1. 新增 `ChimeImporter`，复用现有 `MoegirlKnowledgeStore.upsert` 的事务和
   FTS 更新逻辑；
2. 从固定 tag/commit 下载 `chime_full.json`，校验 SHA-256；下载路径由
   ConfigManager 管理，数据不放入记忆目录；
3. 映射 `meme`、`meaning`、`origin`、`examples`、`type_cn`、`profanity`、
   `offense` 至条目字段与来源标签；
4. `origin` 缺失则保持未知，不能调用 LLM 补写；例句和出处写入 `content` 的
   带标签区段，摘要只使用含义，避免把例句误当定义；
5. 以 `source_id + 原始 meme` 去重，导入可重复运行；
6. 在 `source_state` 保存数据集版本、许可证、仓库 URL 和导入时间。

CHIME 数据更新不应默默覆盖本地修订；新版本需生成导入报告（新增、更新、
移除、冲突、标签变化）。

### 6.2 目录驱动的后台同步

萌百及未来已准入来源均以“来源目录/分类页/最近更新/数据快照”为同步输入，
而不是把每条用户聊天拿去搜索。同步器维护游标、每日预算、请求间隔、内容哈希、
指数退避和单实例锁；网络失败只记录该来源的 `degraded` 状态并保留旧库。

同步的默认策略是**覆盖优先**：只要条目有可用标题和简短释义，即可写入为可检索
的公共梗知识；不要求每条都找到多个来源、人工复核或完整出处。内容不足时保留
“含义待完善”标记，但仍允许标题/别名命中。来源冲突则保留多条记录并优先显示
摘要更完整、来源更新更近的一条。

每次任务从待处理目录中取得有限批次，完成后再安排下一批。建议初始默认：
单来源串行、每次不超过 100 条、请求间隔不短于配置值、失败冷却至下一调度周期。
具体上限必须尊重来源公开的访问规则，不能以提升覆盖率为由绕过限流。

同步器的来源级 fallback 顺序为：已提交的旧本地库 → 下一次计划同步重新尝试同一
来源 → 同一来源允许的目录/最近更新入口切换 → 其他独立来源继续同步。它不在失败时
回退到逐聊天实时搜索，也不会把来源故障传递给流式回复。

### 6.3 萌百适配器

延续现有的 `generator=search` 优先、`opensearch` 兜底、多候选摘要验证、全文
二次验证流程。将现有全局 `sync_state.json` 拆为 `source_state` 中的来源级
状态：萌百失败只能使 `moegirl` 降级，不能让 CHIME 条目不可用。未知或不相关
候选一律不写库。

### 6.4 未来梗百科同步

只有来源条款允许并完成准入测试后启用：列表/分页发现 → 条目获取 → 许可与
来源字段校验 → 内容净化 → 相关性与重复校验 → 条目写入。每次同步必须
限速、带条件请求/哈希、指数退避和单实例锁。

未经授权时，系统最多显示“可打开的外部参考链接”，且不缓存正文、截图或全文
摘要。

## 7. 对话检索与缺口队列

第一步新增内部 `PublicMemeKnowledgeRetriever`，复用现有 FTS/LIKE 查询并增加
`source_id`、`scope`、`risk_tags` 权重。第二步才注册内置工具
`search_public_meme_knowledge(query, limit=3)`；旧 `search_moegirl_knowledge`
在一个兼容周期内保留，并过滤 `scope=acg` 与 `source_id=moegirl`。

返回格式：

```text
【公共梗知识：<词>】
含义：<短摘要>
适用：<公共/ACG/指定圈层>；<必要的冒犯或过时提示>
来源：<来源名>｜<URL>｜同步于 <日期>
```

普通聊天的规则：本地词典命中时使用短卡片；本地未命中时照常回复，**不自动
联网、不调用额外模型**。短卡片首先提供“它大致是什么意思、带什么语气、可否
自然接话”；出处、精确年代和多来源互证均为可选信息。模型不得根据梗卡虚构
出处，发现 `creator:`/`community:` 范围不匹配时应说明“该用法属于特定圈层”，
也不得为了显得亲近而强行玩梗。

只有用户明确提出释义、出处或背景查询时，内置工具才可走“本地库 → 百科来源
→ 已启用的 `web_search` 插件”的串行兜底链路。未命中的规范化查询词可进入
`knowledge_gap_queue`，供后台在其自身预算内补查；队列不保存原始句子、正文或
用户标识，查询失败会进入冷却期，避免反复请求同一站点。

## 8. 安全、质量与可观测性

- 对所有外部文本做控制字符、ChatML/角色标记与长度清理；
- 不记录查询原文、条目正文或示例全文到 INFO 日志；只记录来源、结果数、耗时
  和错误类别；
- 低置信、冒犯、粗俗或过期条目必须带标签；默认不主动推荐；
- 来源冲突时并列展示来源，而不是由模型裁决“哪个出处是真的”；
- 管理页显示每个来源的条目数、许可状态、最后成功、失败原因、拒绝候选数与
  数据集版本；写操作继续使用现有 CSRF + Origin 校验。

## 9. 修订后的实施顺序与验收门槛

### PR 1：安全收口与本地整句命中

- 保持模型语义路由关闭并删除其在正常对话热路径上的任何调用；
- 实现从已验证标题和别名重建的多模式词典索引，并与现有 FTS5 排序合并；
- 只将足够长且非歧义的命中生成一张短卡片，未命中保持正常对话；
- 验收：普通消息无论命中与否均不产生额外模型或网络请求；无引号自然句中的
  已有梗可命中；角色能基于卡片给出符合大致含义和语气的自然回复。

### PR 2：可再生基础库与来源级状态

- 将 schema 版本从 1 升级，增加 `source_id`、`source_item_id`、`source_version`、
  `scope`、`risk_tags`、`expires_at` 和 `source_state`；提供升级/重建策略；
- 为已有萌百记录回填 `source_id=moegirl`、`scope=acg`，并迁移唯一索引；
- 新增 CHIME importer，复用现有 store、净化和 FTS 写入；
- 不改正常对话的网络行为，不接入逐聊天网页抓取；
- 验收：固定 fixture 完整导入 1,458 条、重复导入零重复、字段/标签映射正确、
  升级与导入失败不损坏旧库。

### PR 3：目录驱动的后台同步与缺口队列

- 将萌百同步改为分类、目录或最近更新驱动的可续跑任务；不以聊天正文为输入；
- 增加来源级请求预算、间隔、退避、取消、游标与状态报告；
- 增加只接受“明确求知未命中词”的最小化缺口队列及失败冷却；
- 验收：后台任务不影响首轮回复延迟；停止 Main Server 能直接取消任务；失败不触发
  紧密重试；队列和日志中均无原始用户句子；退出时不等待同步完成，下次重新同步，
  且不会产生半条目或中断中的 FTS 索引。

### PR 4：明确求知的受限联网兜底

- 从现有 `MoegirlKnowledgeRetriever` 抽取通用排序逻辑，支持跨来源 FTS5 检索、
  来源过滤、范围匹配和短卡片渲染；
- 仅对明确求知调用百科与已启用的网页搜索插件，严格串行并设置总超时；
- 注册 `search_public_meme_knowledge`，保留旧工具兼容；
- 验收：相同词的不同圈层条目不被误合并；空库、损坏库、单一来源失败

## 10. 决策门

在开始 PR 1 前需要确认的只有两件事：

1. 接受 CHIME 作为首装、可再生的公共梗基础库；
2. 同意在梗百科网站未授权前，**不**自动下载或持久化其正文。

这两个决策成立时，方案不依赖人工整理词条，也不会靠未经许可的抓取把数据量
伪装成知识质量。
