# MMD 物理引擎：跳舞肢体穿模问题的最终修复方案与原理解析

## 1. 导致穿透的最终元凶
导致跳舞时四肢直接穿透衣服的根本原因，是原代码的 `_setTransformFromBone()` 方法**摧毁了物理引擎的“慢动作插值”机制**。

## 2. 原理解析：瞬移与碰撞插值的矛盾
当你设置 1/60 或 1/120 秒的物理刷新率时，Ammo.js (Bullet Physics) 底层会将一帧画面拆分成几个微小的子步（Substeps）来精细计算碰撞。

但原代码在更新人体四肢（Mode 0 运动学刚体，Kinematic Bodies）时，无差别地使用了 `body.setWorldTransform(form)`。这在物理引擎里等同于**“无视运动过程，瞬间传送”**：

* **瞬移效应**：大腿在一帧内直接从裙子内部“瞬移”到了外部。
* **物理探测失效**：由于没有运动过程的插值，连续碰撞检测（CCD）的扫描完全抓不住跨越的空间。
* **受力缺失**：没有运动速度，自然无法在子步中产生推开布料的物理碰撞推斥力。

要让 Ammo.js 真正计算出肢体挥舞的速度，并在子步计算中平滑地推开衣服，必须针对 Mode 0 刚体使用标准的 `MotionState` 喂食法，并配合禁止休眠机制。

## 3. 核心修复逻辑

### 3.1 唤醒人体骨骼刚体（禁止休眠）
如果运动学刚体（Mode 0）不禁止休眠（Disable Deactivation），引擎底层的运动插值计算是不会启动的。必须强制唤醒这些骨骼绑定的刚体，让引擎持续侦测它们的速度和位移。

### 3.2 区分骨骼和布料的坐标更新方式（消除瞬移）
必须严格区分不同物理模式的坐标同步方式：
* **人体四肢（Mode 0 运动学刚体）**：**只能**通过 `MotionState` 进行坐标更新。这能让引擎捕获到两帧之间的位移差距，自动推算出瞬时速度，从而在动画进行时平滑地推开衣服。
* **布料与头发（Mode 1 / Mode 2 动态刚体）**：只有在发生镜头切换、点歌台重置等需要瞬间重置状态的场景下，才可以直接使用 `setWorldTransform()` 覆盖坐标进行“瞬移”。正常物理演算时由引擎自行接管。
